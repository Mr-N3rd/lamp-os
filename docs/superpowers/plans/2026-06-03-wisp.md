# Wisp Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Rebuild `software/artnet-repeater/` as **wisp** — a small ESP32-C6 board that follows an Aurora palette on the LAN and distributes color tuples to the lamp mesh as transient base-color overrides, also carrying signed lamp firmware for OTA push.

**Architecture:** Wisp lives on WiFi (Aurora ingest via mDNS + WebSocket + Protobuf + HTTP) and on the ESP-NOW mesh (lamp roster + paint commands + firmware push). The app talks to wisp by proxying through any nearby lamp — a new BLE characteristic on each lamp surfaces the last `MSG_WISP_HELLO` it overheard, and a write characteristic forwards ops back to wisp via mesh. WiFi credentials are configured from the app (via mesh proxy), not pre-baked. Firmware channels (`stable`, `beta`) are build-time and enforced via a channel field in both the LSIG footer and `MSG_FW_OFFER`.

**Spec:** [docs/superpowers/specs/2026-06-03-wisp-design.md](../specs/2026-06-03-wisp-design.md) — full architectural background, wire format, subsystem decomposition.

**Tech stack:** PlatformIO + Arduino-ESP32, Seeed Xiao ESP32-C6, NimBLE on the lamp side, mbedTLS ed25519, vendored from `~/Downloads/esp32-palette-client/`: nanopb, ArduinoWebsockets, ArduinoJson, miniz.

**Prerequisite:** None — every phase is self-contained and shippable. Suggested order: 0 → A → B → C → D → E → F → G.

## What we're explicitly NOT doing

- **Wisp self-OTA.** Wisp is flashed via USB; mesh OTA flows wisp → lamps only.
- **Multiple wisps on one mesh.** Single carrier in v1.
- **Per-zone palette assignment.** Aurora supports zones; v1 listens to the first one and ignores the rest.
- **Multi-color tuples (>2 colors per lamp).** Protocol leaves room; not exercised in v1.
- **OTA chunk-size negotiation.** Hard-coded 200 bytes.
- **Cross-channel migration in-place.** Channel changes happen via USB. Lamps reject cross-channel OTA offers.
- **WiFi scan UX.** v1 has manual SSID + password entry.
- **Aurora authentication.** Reference doesn't auth; add later if Aurora ever requires it.
